
## Transient dev-server 500s from concurrent agents
- Mid-task, http://localhost:3000/guide returned 500 for ~4 minutes due to another agent's in-progress edits to lib/actions/auth-actions.ts / lib/validation/auth.ts (missing `forgotPasswordSchema`, then missing `signIn` export) — unrelated to guide/gacha work. Root cause: app/(public)/layout.tsx → SiteHeader → AuthMenu → LogoutButton → auth-actions, so *any* broken auth action import 500s every public page including /guide.
- components/board/LinkMenu.tsx (used by SortMenu) also changed roles mid-task: `role="menu"`/`"menuitem"`/`aria-haspopup="menu"` → `role="listbox"`/`"option"`/`aria-haspopup="listbox"`, plus swapped native Link navigation for an `onNavigate`-intercepted `router.push` in a transition. Playwright selectors targeting the old ARIA roles started timing out — had to loosen selectors to match both role sets.
- Lesson: when verifying against a live dev server shared with other concurrently-editing agents, poll for recovery (`until curl ... = 200`) rather than assuming a failure is caused by your own change; and write DOM selectors resilient to in-flight polish PRs on shared components (SortMenu/LinkMenu) if you must touch pages using them.
