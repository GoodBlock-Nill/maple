내 문의 내역 답장 스레드

운영자가 답변한 문의에 회원이 같은 접수번호 안에서 답장을 이어 가는 기능입니다. 새 문의를 만들지 않고, 운영자가 "처리 중"으로 둔 동안에만 주고받습니다. 1:1 문의 · 버그제보 · 불법이용제보 세 접수 종류에 똑같이 적용됩니다.

01한 장 요약

누가
문의를 쓴 본인만

로그인한 작성자만 답장할 수 있습니다. 운영자는 관리자 콘솔에서 답변합니다.

언제
"처리 중" + 운영자 답변 1건 이상

운영자가 먼저 답을 남기고 상태를 처리 중으로 두었을 때만 답장 폼이 열립니다.

얼마나
운영자 답변 하나당 답장 3건

본문 2,000자, 첨부는 형식에 관계없이 5개 · 합계 200MB. 연속 작성은 30초 간격입니다.

핵심 한 줄. 대화를 여는 것도 닫는 것도 운영자입니다. 회원은 열린 동안 답하고, "답변 완료"가 되면 다시 열 수 없습니다.

02상태 흐름과 답장 가능 구간

문의 상세 상단의 상태 pill 다섯 가지 중 답장 폼이 뜨는 것은 처리 중 하나뿐입니다.

접수 대기답장 ✕회원이 접수한 직후. 이때만 수정·접수 취소 가능
운영자 답변
처리 중답장 ✓운영자가 "등록 후 상태 = 처리 중"으로 답변하면 열림
답변 완료로 등록
답변 완료답장 ✕대화 닫힘. 처리 중으로 되돌리지 않음
운영자 종료
종료답장 ✕운영자만 처리 중으로 다시 열 수 있음
접수 취소  회원이 접수 대기 중에 스스로 취소한 문의. 이후 어떤 답장도 불가하며 안내문도 따로 붙지 않습니다.
답장 창은 운영자의 답변 폼에서 정해집니다. "등록 후 상태" 기본값은 처리 중이고, 답변 완료는 운영자가 일부러 골라야 합니다.
회원이 답장을 보내도 상태는 바뀌지 않습니다. 처리 중 그대로이며, 관리자 목록에 "회원 답장" 뱃지만 켜집니다.

04답장 폼이 보이는 조건, 판정 순서대로

화면은 아래 순서로 묻고, 첫 번째 "아니오"에서 멈춰 그에 맞는 안내 한 줄을 보여 줍니다. 서버도 보낼 때 같은 순서로 다시 검사하므로 "폼은 보이는데 보내면 거절되는" 일은 없습니다.

1
접수 취소된 문의인가?
예폼 없음. 안내문도 없음. 스레드 자리에 이미 접수가 취소된 문의입니다.가 서 있음
2
상태가 답변 완료 또는 종료인가?
예답변이 완료된 문의입니다. 추가 문의는 새 문의로 접수해 주세요.
3
상태가 접수 대기인가?
예운영자 답변 후 답장할 수 있습니다.
4
처리 중인데 운영자 답변이 아직 없는가?
예운영자 답변 후 답장할 수 있습니다. (3번과 같은 문구)
5
마지막 운영자 답변 이후 내 답장이 이미 3건인가?
예운영자 답변을 기다려 주세요. 답장은 운영자 답변 사이에 3건까지 보낼 수 있습니다.
✓
모두 통과 → 스레드 아래에 답장 폼 표시
보낼 때30초 안에 다시 쓰면 너무 빠르게 작성하고 있습니다. N초 후에 다시 시도해 주세요. 가 폼 위에 뜹니다(문의 접수와 답장을 합쳐 셉니다).

05화면 상태 여섯 가지

상세 페이지 아래쪽(스레드 영역 + 폼/안내)이 상태별로 어떻게 보이는지입니다. 접수 정보·첨부 등 위쪽 영역은 모두 동일합니다.

A. 접수 대기접수 대기
💬 운영자가 확인 중입니다. 답변이 등록되면 이곳에 표시됩니다.
운영자 답변 후 답장할 수 있습니다.
폼 없음. 이 상태에서만 "수정"과 "접수 취소" 버튼이 있습니다(기존 규칙).
B. 처리 중 · 답변 전처리 중
💬 운영자가 처리 중입니다. 답변이 등록되면 이곳에 표시됩니다.
운영자 답변 후 답장할 수 있습니다.
운영자가 상태만 처리 중으로 바꾸고 아직 답을 안 쓴 경우. 폼 없음.
C. 처리 중 · 답장 가능처리 중
답장 폼 · 답장 내용 + 첨부 + [답장 보내기]
기본 대화 상태. 운영자 답변 이후 내 답장이 3건 미만.
D. 처리 중 · 3건 채움처리 중
운영자 답변을 기다려 주세요. 답장은 운영자 답변 사이에 3건까지 보낼 수 있습니다.
폼이 잠시 사라집니다. 운영자가 다시 답하면 C로 돌아갑니다.
E. 답변 완료 / 종료답변 완료
답변이 완료된 문의입니다. 추가 문의는 새 문의로 접수해 주세요.
대화 기록은 그대로 남고 폼만 없습니다. 답변 없이 종료된 경우 스레드 자리에 "운영자 검토 후 종료된 문의입니다. 추가 문의는 새 1:1 문의로 남겨 주세요."
F. 접수 취소접수 취소
💬 접수가 취소된 문의입니다.
안내문을 따로 붙이지 않습니다. 같은 말을 두 번 하지 않기 위해서입니다.

08운영자 쪽에서 보이는 것

클라이언트 규칙은 관리자 콘솔의 답변 폼과 짝을 이룹니다. 디자인 검토 때 함께 보면 흐름이 맞아떨어집니다.

답변 폼 · 등록 후 상태
기본값 "처리 중"

선택지 옆 안내: "처리 중: 회원이 이 문의에 답장할 수 있습니다 · 답변 완료: 대화가 닫히며 다시 열 수 없습니다". 답변 완료는 일부러 골라야 합니다.

목록 · 회원 상세
"회원 답장" 뱃지

회원 답장이 오면 상태 뱃지 옆에 켜지고, 운영자가 다시 답하면 꺼집니다. 필터 "회원 답장 도착만"으로 모아 볼 수 있습니다.

상세 스레드
"회원 답장" 라벨 + 첨부

운영자 답변과 다른 배경으로 구분됩니다. 답변 수 집계는 운영자 답변만 셉니다.

답변 템플릿
추가 정보 요청은 "이 문의에 답장으로"

처리 완료 계열 템플릿만 "추가 문의는 새 문의로" 안내를 유지합니다.

09왜 이렇게 정했나

답변 완료된 문의를 왜 다시 열 수 없나요?

"완료"의 뜻을 하나로 두기 위해서입니다. 완료 뒤에도 답장이 열려 있으면 운영자는 끝난 건을 계속 지켜봐야 하고, 회원은 어디까지 응답을 기대해도 되는지 알 수 없습니다. 이어지는 질문은 새 문의로 받고, 운영자는 처리 중일 때 충분히 주고받은 뒤 완료로 닫습니다.

왜 운영자 답변 하나당 3건까지만인가요?

회원이 한 번에 여러 개를 쏟아내면 운영자가 무엇에 답해야 할지 흐려집니다. 3건이면 "본문 + 첨부 + 보충" 정도는 담기고, 운영자가 다시 답하면 창이 새로 열리므로 대화 자체는 끊기지 않습니다.

30초 간격은 어디에 적용되나요?

문의 접수와 답장을 합쳐 계산합니다. 접수 직후 30초 안에는 답장을, 답장 직후 30초 안에는 다음 답장을 보낼 수 없습니다. 폼은 그대로 보이고 보낼 때 남은 초와 함께 안내가 뜹니다.

접수 취소 상태에는 왜 안내문이 없나요?

스레드 자리에 이미 "접수가 취소된 문의입니다."가 있어서, 그 아래에 "답장할 수 없습니다"를 또 쓰면 같은 말을 두 번 하게 됩니다. 취소는 회원이 스스로 한 결정이라 이유를 더 설명할 필요도 없습니다.

회원이 답장하면 상태가 바뀌나요?

바뀌지 않습니다. 처리 중 그대로이고, 관리자 목록에 "회원 답장" 뱃지가 켜져 운영자가 놓치지 않게 합니다. 상태 변경은 언제나 운영자가 답변을 등록하면서 정합니다.
