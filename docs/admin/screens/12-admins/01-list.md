# 관리자 — 목록 (`/admins`)

**목적** 관리자 계정을 초대·삭제(= 콘솔 접근 차단)하고, 역할(모듈별 권한)을 만들어 배정한다. 한 페이지에 표 세 개(관리자 · 수락 대기 초대 · 권한)가 세로로 놓인다.

**데이터 출처** `requireSuperAdmin()` 과 세 조회를 `Promise.all` 로 함께 부른다(`admin/lib/data/admins.ts`, 모두 세션 클라이언트).

- `getAdmins()` — `profiles` 에서 `role='admin'` 인 행을 `created_at` 오름차순으로 읽고 `admin_roles(key, name)` 을 임베드한다. 실패 시 `console.error('[admins] 목록 조회 실패')` 후 빈 배열이다.
- `getPendingInvites()` — `admin_invites` 에서 `status='pending'` 인 행을 `created_at` 내림차순으로 읽는다. `isExpired` 는 `expires_at <= now` 로 계산한다.
- `getAdminRoles()` — `admin_roles` 를 `is_system desc, created_at asc` 로 읽는다.
- `getAdminRoles()` — 사용 인원은 별도 질의(`countRoleMembers()`: `role='admin'` 且 `admin_role_id is not null`)로 센다. PostgREST 임베드 집계는 역방향 관계에 필터를 걸 수 없어 `role='user'` 인 잔여 참조까지 세기 때문이다.

**페이지 헤더** 제목은 `관리자`, 설명은 "관리자 계정을 초대·삭제하고 권한(역할)을 관리합니다. 삭제는 계정을 지우지 않고 콘솔 로그인을 막습니다." 이고 action 은 `관리자 초대` 버튼이다(→ [02-invite-form.md](02-invite-form.md)).

## 1.1 관리자 목록 (`AdminsTable`)

카드 머리는 `관리자 {N}명` 이고 설명은 "역할을 바꾸면 다음 요청부터 사이드바와 화면 권한이 함께 바뀝니다." 다.

| 열 | 값의 출처 | 표시 규칙 |
|---|---|---|
| 닉네임 | `profiles.nickname` | 굵게 + 본인이면 `나` 뱃지 |
| 이메일 | `profiles.email` | `null` 이면 `-` |
| 권한 | `admin_roles.name` | 뱃지(w-36) |
| 등록일 | `profiles.created_at` | `formatDateTime`(w-40) |
| 역할 변경 | 역할 전체 | 셀렉트 + 저장 버튼 |
| 조치 | — | 삭제 버튼(w-24) |

**동작 상세**

- **권한** 역할이 없으면 `역할 없음`(warn), 슈퍼어드민이면 accent, 그 외는 neutral 이다.
- **등록일** 초대 메일 발송 시점에 `auth.users` 행이 만들어지므로 그 시각이 계정 생성 시각이다.
- **역할 변경** 컴포넌트는 `AdminRoleSelect` 다(아래 §1.1.1).
- **조치** 컴포넌트는 `DeleteAdminButton` 이다(아래 §1.1.2).
- **빈 목록** 문구는 `관리자가 없습니다.` 다.
- **없는 열** 마지막 로그인 시각은 넣지 않는다. `auth.users` 에만 있어 서비스 롤로 전 계정을 훑어야 하는데, 목록 한 줄을 채우자고 RLS 밖 조회 경로를 열지 않는다(필요하면 `/audit` 이 더 정확한 이력을 준다).

### 1.1.1 역할 변경 (`AdminRoleSelect` → `changeAdminRoleAction`)

| 필드/컨트롤 | 종류 | 필수·제한 | 기본값 | 동작 |
|---|---|---|---|---|
| adminId | hidden | `z.uuid()` | 행의 id | — |
| 역할 | 셀렉트 | `z.uuid()` | 현재 `admin_role_id` | 값만 바꾼다 |
| 저장 | 제출 버튼 | 값이 바뀌어야 활성 | — | `changeAdminRoleAction` |
| (본인 행) | 문구 | — | — | 셀렉트 대신 안내 |

**동작 상세**

- **역할** `aria-label="역할"` 이고 현재 역할이 없으면 placeholder 가 `역할 없음` 이다.
- **역할** 고르자마자 저장하지 않는다. 셀렉트는 키보드 화살표로 값이 스쳐 지나가므로 그 순간 저장하면 의도하지 않은 역할이 잠깐 적용된다.
- **저장** 값이 비었거나 현재와 같으면 비활성이고 진행 중에는 `저장 중…` 이다.
- **저장** 성공 토스트는 `{닉네임} 님의 역할을 {역할명} 로 바꿨습니다.` 다.
- **저장** 실패 시 에러 토스트를 띄우고 셀렉트를 원래 값으로 되돌린다.
- **(본인 행)** 문구는 `자기 역할은 바꿀 수 없습니다.` 다.
- **DB 변경** `profiles.admin_role_id` 하나다.
- **감사** `admin.role.change` 이고 before 는 `{role: 이전 key}`, after 는 `{role: 새 key}` 다.

### 1.1.2 관리자 삭제 (`DeleteAdminButton` → `deleteAdminAction`)

| 필드/컨트롤 | 종류 | 필수·제한 | 동작 |
|---|---|---|---|
| 삭제 | 버튼(danger, sm) | 본인 행은 버튼 없음 | 확인 다이얼로그를 연다 |
| 다이얼로그 제목 | 고정 | — | `관리자 삭제` |
| 다이얼로그 설명 | 고정 | — | 아래 상세 |
| adminId | hidden | `z.uuid()` | — |
| 취소 / 삭제 | 버튼 | 진행 중 비활성 | 실패 시 배너 표시 |

**동작 상세**

- **삭제** 본인 행에서는 버튼 대신 `본인` 텍스트가 나오고 `title` 은 "자기 자신은 삭제할 수 없습니다." 다.
- **다이얼로그 설명** 문구는 `{닉네임} 관리자를 삭제합니다. 관리자 콘솔에 로그인할 수 없게 되며 작성 이력은 남습니다.` 다.
- **다이얼로그 설명** "삭제"라는 단어만 보면 글까지 사라진다고 오해하므로 실제로 일어나는 일을 그대로 적는다.
- **취소 / 삭제** 진행 중에는 `삭제 중…` 으로 바뀐다.
- **3단계 처리** 와 거절 규칙은 → [README](README.md) §2.
- **성공** 토스트는 `{닉네임} 관리자를 삭제했습니다.` 다.
- **감사** `admin.delete` 이고 before 는 `{role:'admin', adminRole: key}`, after 는 `{role:'user', banned:true}` 다.

## 1.2 수락 대기 초대 (`InvitesTable`)

카드 머리는 `수락 대기 초대 {N}건` 이고 설명은 "받은 사람이 링크에서 비밀번호를 정하면 관리자가 됩니다. 링크가 만료되면 재발송하세요." 다.

| 열 | 값의 출처 | 표시 규칙 |
|---|---|---|
| 이메일 | `admin_invites.email` | 굵게 + 만료 뱃지 |
| 권한 | `admin_roles.name` | 없으면 `-`(w-36) |
| 발송일 | `created_at` | `formatDateTime`(w-40) |
| 만료 | `expires_at` | `null` 이면 `없음`(w-40) |
| 조치 | — | 재발송 · 취소(w-40) |

**동작 상세**

- **이메일** `expires_at <= now` 면 `만료`(warn) 뱃지가 붙는다.
- **만료** `null` 인 경우는 부트스트랩 초대다.
- **목록 정책** 만료된 초대도 지우지 않고 계속 보여 준다. 재발송 한 번이면 되살아나는데 목록에서 사라지면 "초대를 보냈던가?"부터 다시 확인해야 한다.
- **빈 목록** 문구는 `대기 중인 초대가 없습니다.` 다.

### 초대 조치 (`InviteActions`)

| 조치 | 액션 | DB 변경 | 감사 |
|---|---|---|---|
| 재발송 | `resendInviteAction` | `expires_at` 7일 연장 + 메일 재발송 | `admin.invite.resend` |
| 취소 | `revokeInviteAction` | `status = 'revoked'` | `admin.invite.revoke` |

**동작 상세**

- **공통 검증** `inviteId` 가 비어 있으면 "초대를 찾을 수 없습니다.", `status` 가 `pending` 이 아니면 "이미 수락되었거나 취소된 초대입니다." 다.
- **재발송** 서비스 롤로 `auth.admin.inviteUserByEmail()` 을 다시 불러 새 링크를 보낸다.
- **재발송** 감사 after 는 `{email}` 이고 성공 토스트는 `{이메일} 으로 초대 메일을 다시 보냈습니다.` 다.
- **취소** 행은 남긴다 — `admin_invites` 에 DELETE 정책 자체가 없다.
- **취소** 감사 before 는 `{email, status:'pending'}`, after 는 `{status:'revoked'}` 이고 성공 토스트는 `{이메일} 초대를 취소했습니다.` 다.
- **확인 다이얼로그 없음** 둘 다 되돌리기 쉬운 조작이고(취소한 초대는 다시 보내면 된다), 모든 조작을 다이얼로그로 감싸면 습관적으로 확인을 눌러 결국 아무것도 막지 못한다.
- **버튼 상태** 두 버튼은 서로의 진행 중에 함께 비활성된다.

## 1.3 권한(역할) 목록 (`RolesTable`)

카드 머리는 `권한 {N}개` 이고 설명은 "모듈마다 없음 · 읽기 · 쓰기를 정합니다. 슈퍼어드민은 시스템 역할이라 바꿀 수 없습니다." 다. 헤더 action 은 `역할 추가` 다(→ [03-permissions-editor.md](03-permissions-editor.md)).

| 열 | 값의 출처 | 표시 규칙 |
|---|---|---|
| 이름 | `name` | 굵게 + 아래 `key`(모노스페이스) |
| 설명 | `description` | `null` 이면 `-` |
| 권한 | `summarizePermissions()` | 한 줄 요약(w-32) |
| 사용 | `memberCount` | `{N}명`(우측, w-20) |
| 조치 | — | 수정 · 삭제(w-44) |

**동작 상세**

- **이름** `is_system` 이면 `시스템` 뱃지(accent)가 붙는다.
- **권한** 전 모듈 write 면 `전체 쓰기`, 아니면 `쓰기 N · 읽기 M`, 하나도 없으면 `권한 없음` 이다.
- **권한** 정확한 값은 수정 다이얼로그의 매트릭스에서 본다 — 14개를 표에 펼치면 읽히지 않는다.
- **조치** 시스템 역할이 아니면 `수정` 버튼이 나온다. 삭제 버튼은 아래 표를 따른다.
- **빈 목록** 문구는 `역할이 없습니다.` 다.

### 삭제 버튼(`DeleteRoleButton`)의 3가지 표시

| 조건 | 화면 | 이유 |
|---|---|---|
| `is_system` | `시스템 역할` 텍스트 | 지우면 콘솔에 아무도 못 들어온다 |
| `memberCount > 0` | `사용 중 {N}명` 텍스트 | 먼저 할 일을 그 자리에서 알린다 |
| 그 외 | `삭제` 버튼 | 확인 다이얼로그로 이어진다 |

**동작 상세**

- **다이얼로그** 제목은 `역할 삭제`, 설명은 `{이름} 역할을 삭제합니다. 이 역할을 쓰는 관리자는 없습니다.` 다.
- **서버 재검증** `deleteAdminRoleAction` 이 같은 두 조건을 다시 검사한다.
- **성공** 토스트는 `{이름} 역할을 삭제했습니다.` 이고 감사 `admin.role.delete` 의 before 는 `{key, name}` 이다.

**상태·뱃지 의미**

| 뱃지 | 색 | 뜻 |
|---|---|---|
| 나 | accent | 로그인한 본인 행 |
| 역할 없음 | warn | `admin_role_id` 가 비어 있다 |
| 슈퍼어드민 역할명 | accent | `admin_roles.key === 'super_admin'` |
| 만료 | warn | 초대 허용 목록 수명(7일)이 지났다 |
| 시스템 | accent | `is_system = true` |

- **나** 그 행은 역할 변경·삭제가 막힌다.
- **역할 없음** 콘솔에는 들어오지만 아무 모듈도 보이지 않는다(닫힘 실패).
- **만료** `pending` 이어도 승격 근거가 되지 않는다.
- **시스템** 수정·삭제가 모두 불가하다.

**클라이언트와의 상호작용**

- 이 화면은 관리자 콘솔 전용이며 사용자 사이트와 연결된 화면이 없다. 회원을 관리자로 승격하는 경로 자체가 없다.
- 초대 메일의 링크는 관리자 앱(`NEXT_PUBLIC_ADMIN_URL`)의 `/auth/callback?next=/invite/accept` 를 가리킨다 → `14-auth/04-invite-accept.md`.
- 역할을 바꾸면 다음 요청부터 사이드바(`visibleNavItems`)와 화면 권한이 함께 바뀐다. 권한은 `requireAdmin()` 이 요청마다 `profiles` 와 `admin_roles` 를 한 번에 읽는다.

**오류·예외**

- 역할 변경 — 본인: "자기 자신의 권한은 바꿀 수 없습니다."
- 역할 변경 — 대상이 관리자가 아님: "관리자를 찾을 수 없습니다."
- 역할 변경 — 같은 역할: "이미 같은 역할입니다."
- 역할 변경 — 역할 없음: "역할을 찾을 수 없습니다."
- 역할 변경 — 마지막 슈퍼어드민 강등: "마지막 슈퍼어드민입니다. 다른 슈퍼어드민을 먼저 지정해 주세요."
- 역할 변경 — DB 실패: "역할을 바꾸지 못했습니다. 권한은 그대로입니다. 다시 시도해 주세요."
- 삭제 — 본인: "자기 자신은 삭제할 수 없습니다."
- 삭제 — 마지막 슈퍼어드민: 위와 같은 `LAST_SUPER_ADMIN_MESSAGE` 문구다.
- 삭제 — DB 실패: "관리자를 삭제하지 못했습니다. 권한은 그대로입니다. 다시 시도해 주세요."
- 역할 삭제 — 시스템: "시스템 역할은 삭제할 수 없습니다."
- 역할 삭제 — 사용 중: "이 역할을 쓰는 관리자가 {N}명 있습니다. 먼저 다른 역할로 바꿔 주세요."
- 역할 삭제 — DB 실패: "역할을 삭제하지 못했습니다. 다시 시도해 주세요."
- 초대 조치 실패: "초대 메일을 다시 보내지 못했습니다. 잠시 후 다시 시도해 주세요." / "초대를 취소하지 못했습니다. 다시 시도해 주세요."
- 세 조회 중 하나가 실패해도 화면은 그려진다(그 표만 비어 보인다). 원인은 서버 로그에 남는다.
- `관리자 초대` 버튼은 역할이 하나도 없으면 비활성된다(`roleOptions.length === 0`).
- 역할을 지우면 FK `on delete set null` 로 그 역할을 쓰던 관리자는 `역할 없음` 이 된다 — 화면이 사용 인원 0명일 때만 삭제를 허용하는 이유다.
- DB 도 같은 규칙을 한 번 더 강제한다(`admin_roles_insert_super`·`_update_super`·`_delete_super` 정책, `is_super_admin()`, 가드 트리거). 앱에서만 막으면 REST 직접 호출로 우회된다.
