# FAQ 등록·수정 다이얼로그

> 07 고객지원 › [10-faq.md](10-faq.md) 의 "FAQ 등록" · 섹션의 "추가" · 행의 "수정" 이 모두 이 컴포넌트를 연다(`admin/components/faqs/FaqFormDialog.tsx`). 삭제 확인(`FaqDeleteButton`)도 여기서 함께 적는다.

**목적** 사용자 사이트 "자주 묻는 질문"에 그대로 나갈 한 쌍(질문·답변)을 쓰고, 어느 카테고리에 둘지와 지금 발행할지를 정한다.

**데이터 출처·모드**
- `faq` prop 이 있으면 **수정**(hidden `faqId`), 없으면 **등록**.
- `defaultCategory` prop: 섹션의 "추가"가 자기 카테고리를 넘긴다. 헤더의 "FAQ 등록"은 넘기지 않아 `FAQ_CATEGORIES[0]`(공지사항)이 기본값이 된다.
- 검증: `admin/lib/validation/faqs.ts` 의 `faqSchema`.
- 제목: 등록 "FAQ 등록" / 수정 "FAQ 수정". 설명: "사용자 사이트의 '자주 묻는 질문'에 그대로 표시됩니다."
- 폼은 `noValidate` — 검증 문구를 브라우저가 아니라 서버 스키마가 소유한다.

## 1. 필드

| 필드/컨트롤 | 종류 | 필수·제한(검증 · DB) | 기본값·프리필 | 동작 / 상호작용 |
|---|---|---|---|---|
| `faqId` | hidden | 수정 모드에서만. 빈 값이면 "대상을 찾을 수 없습니다." | 현재 행 | — |
| 카테고리 | 네이티브 `select` `category` | `z.enum(FAQ_CATEGORY_VALUES)` · DB `faqs.category` 는 `faq_category` enum | 수정: 현재 값 / 등록: `defaultCategory ?? 'notice'` | 선택지·정렬 재계산(아래) |
| 질문 | `Input` `question`, required, maxLength 200 | 필수·길이(아래) | 현재 질문 | hint(아래) |
| 답변 | `Textarea` `answer`, rows 6, required, maxLength 2000 | 필수·길이(아래) | 현재 답변(상태로 쥔다) | hint: "사용자 화면은 한 문단으로 이어 붙여 보여 줍니다(줄바꿈 표시 없음)." — §4 참고 |
| 미리보기 | 읽기 전용 문단 | — | 비었으면 "답변을 입력하면 사용자 화면 모습이 보입니다." | 답변 상태를 그대로 그린다. **`whitespace-pre-line` 이 없다** |
| 사용자 사이트에 발행 | checkbox `isPublished` | 없으면 false | 수정: 현재 값 / 등록: **체크됨** | `is_published`. 해제하면 `faqs_select_published` RLS 로 사용자 쪽에서 즉시 사라진다 |
| 취소 | 버튼(secondary) | — | — | 다이얼로그 닫기 |
| 등록 / 수정 | 버튼(submit) | `faqs:write` | "등록" · "수정" / 진행 중 "저장 중…" | 성공/실패 처리(아래) |

**동작 상세**
- **카테고리** — 선택지 5개(공지사항·계정·결제·버그·기타). **카테고리를 옮기면** 저장 시 새 카테고리의 맨 뒤로 `sort_order` 가 다시 잡힌다(그대로 두면 순번이 겹쳐 정렬이 뒤섞인다).
- **질문(필수·제한)** — `plainTextField(200, …)` — CRLF→LF + trim 후 1~200자. 빈 값 "질문을 입력해 주세요." / 초과 "질문은 200자를 넘을 수 없습니다."
- **질문(동작)** — hint: "사용자 사이트 FAQ 아코디언의 접힌 줄에 그대로 보입니다. PC 약 28자 · 폰 약 13자마다 줄이 바뀌므로 한 줄짜리 질문이 읽기 좋습니다."
- **답변(필수·제한)** — `plainTextField(2000, …)` — 빈 값 "답변을 입력해 주세요." / 초과 "답변은 2000자를 넘을 수 없습니다."
- **등록 / 수정** — 성공 시 토스트("FAQ를 등록했습니다." / "FAQ를 수정했습니다.") + 닫힘. 등록 모드면 답변 상태를 비운다.

## 2. 저장 후

| 모드 | DB | 감사 | 재검증 |
|---|---|---|---|
| 등록 | insert, `sort_order = getNextFaqSortOrder(category)` | `faq.create` — `after: { category, question, is_published, sort_order }`(**답변 본문은 남기지 않는다**) | `revalidatePath('/faqs')` + `revalidateClient(['faqs'])` |
| 수정 | update(+ 카테고리를 옮겼으면 `sort_order` 재계산) | `faq.update` — before `{ category, question, answer, is_published }` / after 동일 필드 | 동일 |

## 3. 삭제 확인 (`FaqDeleteButton`)

| 요소 | 값 |
|---|---|
| 트리거 | 행의 "삭제" 버튼(danger, sm) |
| 제목 | "FAQ 삭제" |
| 설명 | "되돌릴 수 없습니다. 잠시 숨기려는 것이라면 발행을 해제하세요." |
| 본문 | 그 항목의 질문 |
| 숨은 값 | `faqId` |
| 버튼 | "취소" · "삭제"(danger, 진행 중 "삭제 중…") |
| 성공 | 토스트 "FAQ를 삭제했습니다." + 닫힘 |

사용 건수 같은 제약이 없다(FAQ 를 참조하는 다른 행이 없다). 남은 항목의 `sort_order` 구멍도 메우지 않는다.

## 4. 상태·뱃지 의미 · 렌더 규칙

| 표시 | 값 | 의미 |
|---|---|---|
| (목록의) 발행 / 미발행 | `is_published` | 사용자 사이트 노출 여부. 이 폼에서는 체크박스 하나로만 나타난다 |

**답변 렌더 규칙 — 관리자 미리보기와 사용자 화면이 지금 어긋나 있다.**

| 화면 | 구현 | 결과 |
|---|---|---|
| 관리자 미리보기 | `<p class="… leading-relaxed">{answer}</p>` (`whitespace-pre-line` 없음) | 줄바꿈이 **접혀** 한 문단으로 보인다 |
| 사용자 아코디언 | `components/support/FaqAccordion` 의 `<p class="… whitespace-pre-line">{item.answer}</p>` | 줄바꿈이 **유지된다** |

즉 hint 문구("줄바꿈 표시 없음")와 미리보기는 사용자 화면보다 보수적이다 — 운영자가 줄을 나눠 쓰면 미리보기보다 잘 읽히는 결과가 나간다. 마크다운·HTML 은 양쪽 모두 해석하지 않는다.

## 5. 클라이언트와의 상호작용

| 여기서 바꾼 값 | 사용자 사이트에서 | 언제 |
|---|---|---|
| 카테고리 | 카테고리 칩과 묶음(아래) | 태그 `faqs` 재검증(즉시 시도, 실패 시 ≤300초) |
| 질문 | 접힌 줄(요약)의 문구 | 같음 |
| 답변 | 펼친 문단 | 같음 |
| 발행 해제 | 아코디언에서 사라진다 | RLS 라 **즉시**(캐시가 남아 있어도 다음 조회에서 행 자체가 없다) |

**동작 상세**
- **카테고리** — `/support/faq` 아코디언의 카테고리 칩과 묶음. 카테고리가 나열되는 순서는 코드 상수가 소유한다.
