# 답변 템플릿 등록·수정 다이얼로그

> 07 고객지원 › [08-reply-templates.md](08-reply-templates.md) 의 "템플릿 등록" · "템플릿 추가" · 행의 "수정" 이 모두 이 컴포넌트를 연다(`admin/components/inquiry-reply-templates/InquiryReplyTemplateFormDialog.tsx`).

**목적** 답변 화면에서 불러다 쓸 문안 한 건을 만들고, 어느 묶음(공통/카테고리)에 둘지와 지금 쓸지를 정한다.

**데이터 출처·모드**
- `template` prop 이 있으면 **수정**(hidden `templateId`), 없으면 **등록**.
- `categories` prop: `getInquiryReplyTemplateCategories()` 가 준 목록(**비활성 포함**, 종류 순 정렬).
- `defaultCategoryId` prop: 묶음 머리글의 "템플릿 추가"가 자기 묶음을 넘긴다. 헤더의 "템플릿 등록"은 넘기지 않아 공통이 기본값이 된다.
- 검증: `admin/lib/validation/inquiry-reply-templates.ts` 의 `inquiryReplyTemplateSchema`.
- 제목: 등록 "답변 템플릿 등록" / 수정 "답변 템플릿 수정". 설명: "문의 상세의 답변 칸에 '템플릿 불러오기' 로 채워 넣는 문안입니다."

**동작 상세**
- **카테고리(필수·제한)** — 빈 문자열(공통) 또는 uuid. 그 밖이면 "카테고리를 다시 골라 주세요." · FK `inquiry_reply_templates.category_id`.
- **카테고리(동작)** — 첫 항목이 **"공통(모든 카테고리)"**(값 = 빈 문자열 → `toCategoryId()` 가 **NULL 로 저장**). 나머지는 `{종류} · {라벨}` 이고 비활성 카테고리는 `… (숨김)` 이 붙는다. hint: "공통으로 두면 모든 문의에서 보입니다. 카테고리를 고르면 그 분류의 문의에서만 보입니다."
- **템플릿 이름** — CRLF→LF + trim 후 1~40자. 빈 값 "템플릿 이름을 입력해 주세요." / 초과 "이름은 40자를 넘을 수 없습니다." · DB `inquiry_reply_templates_name_length` + 묶음 안 유니크.
- **템플릿 내용(필수·제한)** — CRLF→LF + trim 후 1~2000자. 빈 값 "템플릿 내용을 입력해 주세요." / 초과 "내용은 2000자를 넘을 수 없습니다." · DB `inquiry_reply_templates_body_length`.
- **템플릿 내용(동작)** — 상한이 답변 입력칸과 **같은 숫자**다(`INQUIRY_REPLY_TEMPLATE_BODY_MAX = INQUIRY_REPLY_MAX_LENGTH`) — 여기가 더 관대하면 "불러왔는데 등록할 수 없는" 템플릿이 생긴다. hint: "답변 칸에 그대로 채워집니다. 줄바꿈은 유지되고 마크다운은 해석되지 않습니다."

**비활성 카테고리도 선택지에 남긴다.** 이미 그 카테고리에 붙어 있는 템플릿을 고치려면 셀렉트에 그 항목이 있어야 하고, 없으면 저장할 때 엉뚱한 묶음으로 옮겨진다.

## 2. 자리표시자 삽입 (`InquiryReplyTemplateBodyField`)

| 토큰 | 버튼 `title`(설명) | 치환 값 | 값이 비었을 때 |
|---|---|---|---|
| `{{닉네임}}` | 문의한 회원의 닉네임(이메일 문의는 발신자 이름) | `inquiry.nickname` | `고객` |
| `{{문의번호}}` | 접수번호(예: #1024). 사용자 화면·메일과 같은 값 | `formatInquiryNo(inquiry_no)` | `-` |
| `{{카테고리}}` | 문의 카테고리 이름 | `inquiry.category` | `문의` |
| `{{제목}}` | 문의 제목 | `inquiry.title` | `문의` |

- 버튼은 **커서 자리에** 토큰을 끼워 넣는다(끝에만 붙이면 문장 중간에 넣으려는 운영자가 매번 잘라내기·붙여넣기를 해야 한다). 삽입 뒤 `requestAnimationFrame` 으로 포커스와 캐럿을 토큰 끝으로 되돌린다 — 그러지 않으면 포커스가 버튼에 남아 다음 글자가 엉뚱한 곳에 찍힌다.
- textarea 요소는 `ref` 가 아니라 이벤트의 `currentTarget`(`onChange`·`onFocus`·`onSelect`)에서 붙잡는다. 공용 `Textarea` 가 글자수 측정에 자기 ref 를 쓰므로 바깥에서 걸 자리가 없다.
- 토큰 자체는 **저장된다.** 치환은 문의 상세에서 "불러오기"를 누르는 순간 한 번만 일어난다([04-reply-form.md](04-reply-form.md) §3).
- 모르는 `{{…}}` 는 치환기가 그대로 둔다 — 운영자가 손으로 채우려고 적어 둔 표시일 수 있다.

## 3. 미리보기

| 요소 | 값 |
|---|---|
| 머리글 | `미리보기 (예시 문의 · 글자용사 / 재화·아이템)` |
| 본문 | `applyReplyTemplate(value, SAMPLE_INQUIRY)` 의 결과 — 즉 **치환된 뒤의 문장** |
| 표시 | `whitespace-pre-line`(줄바꿈만) |

`SAMPLE_INQUIRY` = `{ inquiryNo: 1024, title: '아이템이 사라졌어요', category: '재화·아이템', nickname: '글자용사' }`. 실제 문의를 끌어오지 않는 이유는 템플릿이 특정 문의에 매이지 않기 때문이다. 자리표시자를 그대로 그리면 운영자는 "정말 이름으로 바뀌나"를 저장하고 문의를 열어 봐야 확인할 수 있다.

미리보기와 실제 삽입이 **같은 함수**(`applyReplyTemplate`)를 쓴다 — 두 곳에 따로 쓰면 본 문장과 들어가는 문장이 갈린다.

## 4. 저장 후

| 모드 | 결과 |
|---|---|
| 등록 | insert·감사·재검증 흐름(아래) |
| 수정 | update·감사·재검증 흐름(아래) |

**동작 상세**
- **등록** — 그 묶음 맨 뒤 순번으로 insert → 감사 `inquiry_reply_template.create`(`after: { category_id, name, body, is_active, sort_order }`) → `/inquiries/reply-templates` 재검증 → 토스트 "템플릿을 등록했습니다." → 닫힘 + 본문 비움.
- **수정** — update(카테고리를 옮겼으면 새 묶음 맨 뒤 순번) → 감사 `.update`(before/after) → 재검증 → 토스트 "템플릿을 수정했습니다." → 닫힘.

## 5. 상태·뱃지 의미

이 다이얼로그에는 뱃지가 없다. 상태를 정하는 것은 "답변 화면에서 사용" 체크박스 하나이고, 목록 행의 사용/중지 뱃지가 그 값을 그린다. 카테고리 선택지의 `(숨김)` 꼬리표는 **카테고리**의 상태이지 템플릿의 상태가 아니다.

## 6. 클라이언트와의 상호작용

- **사용자 사이트와 직접 닿는 곳이 없다.** 이 테이블은 관리자 전용이고 캐시 태그도 없다.
- 간접 경로는 하나다: 저장된 문안 → 문의 상세에서 불러오기(자리표시자 치환) → `inquiry_replies.content` 로 저장 → 사용자 사이트 답변 스레드 또는 답신 메일.
- 그래서 본문은 **사용자가 읽을 문장**으로 써야 한다. 저장되는 답변에 `{{닉네임}}` 이 남으면 그대로 노출된다.
- 이름은 사용자에게 노출되지 않는다(선택 상자 전용).
