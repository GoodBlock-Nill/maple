# 인증 — 새 비밀번호 설정 (`(auth)/reset-password`)

**목적** 재설정 메일 링크를 타고 도착해 새 비밀번호를 저장한다. 카드 제목 `새 비밀번호 설정`, 설명 "새로 사용할 비밀번호를 입력하세요."

**데이터 출처** 조회 없음(정적 페이지). **세션 유무를 화면에서 미리 검사하지 않는다** — 검사하려면 서버에서 쿠키를 읽어야 하는데 링크를 막 통과한 직후에는 프록시가 세션을 세운 뒤라 결과가 흔들린다. 세션이 없으면 액션이 "링크가 만료되었습니다…"로 정확히 안내한다.

## 1.1 폼 (`SetPasswordForm submitLabel="비밀번호 변경"`)

| 필드/컨트롤 | 종류 | 필수·제한(검증) | 기본값 | 동작 / 상호작용 |
|---|---|---|---|---|
| next | hidden | — | `'/'`(prop 기본값. 이 화면은 값을 넘기지 않는다) | 성공 시 `sanitizeNextPath()` 를 거쳐 대시보드로 이동 |
| 오류 배너 | `FormBanner` | — | 없음 | `state.formError` |
| 새 비밀번호 | `type="password"`, `autoComplete="new-password"`, `autoFocus`, `required`, `maxLength=72` | **필수** 10~72자(`setPasswordSchema.password`). 오류: "비밀번호는 10자 이상이어야 합니다." / "비밀번호는 72자를 넘을 수 없습니다." | 빈 값 | 힌트 "10~72자. 어깨너머로 길이가 읽히지 않도록 글자수는 세지 않습니다." — 다른 입력과 달리 `현재/최대` 카운터를 **일부러 그리지 않는다** |
| 새 비밀번호 확인 | `type="password"`, `autoComplete="new-password"`, `required`, `maxLength=72` | **필수** 1자 이상("비밀번호를 한 번 더 입력해 주세요.") + 위 값과 일치(`refine` → `passwordConfirm` 필드 오류 "비밀번호가 일치하지 않습니다.") | 빈 값 | — |
| 비밀번호 변경 | 제출 버튼(전체 폭) | — | — | `setPasswordAction`. 진행 중 `저장 중…` + 비활성 |

길이 규칙의 근거: 하한 10은 Supabase 기본(6)보다 강하게 잡은 값, 상한 72는 bcrypt 가 73바이트째부터 버리기 때문(그보다 길면 뒤가 조용히 무시된다).

## 1.2 서버 동작 (`setPasswordAction`)

| 단계 | 내용 |
|---|---|
| 검증 | `setPasswordSchema`(길이 + 두 값 일치) → 실패 시 필드 오류 |
| 세션 확인 | `supabase.auth.getUser()` — `null` 이면 **"링크가 만료되었습니다. 비밀번호 재설정 메일을 다시 요청해 주세요."** 링크로 만들어진 세션이 없으면 아무나 남의 비밀번호를 바꿀 수 있으므로 반드시 확인한다 |
| 변경 | `supabase.auth.updateUser({ password })` |
| 같은 비밀번호 | Supabase `error.code === 'same_password'` → `password` **필드 오류** "이전과 다른 비밀번호를 입력해 주세요."(운영자가 바로 고칠 수 있는 입력 문제라 필드에 붙인다) |
| 그 외 실패 | 배너 "비밀번호를 변경하지 못했습니다. 링크를 다시 받아 처음부터 진행해 주세요." + 서버 로그 `[auth] …` |
| 성공 | `redirect(sanitizeNextPath(next))` = `/`(대시보드). 별도 완료 화면·토스트 없음 |
| 감사 | 남기지 않는다 |

이 액션은 초대 수락 화면과 **공용**이다(→ [04-invite-accept.md](04-invite-accept.md)).

**클라이언트와의 상호작용**

- 도착 경로: 재설정 메일 → `/auth/callback?next=/reset-password` → 세션 확립 + 관리자 확인 → 이 화면.
- 비밀번호가 바뀌어도 **다른 기기의 세션을 강제로 끊지 않는다**(`updateUser` 만 호출한다).
- 사용자 사이트에는 대응 화면이 없다(`proxy.ts` 가 `/reset-password` 를 `/login` 으로 302).

**오류·예외**

- 이 화면은 `PUBLIC_PREFIXES` 에 있어 로그인 없이 열리지만, **세션 없이 제출하면 항상 "링크가 만료되었습니다"** 로 끝난다(폼만 보고 성공을 기대하게 되는 지점).
- 링크를 두 번 쓰면(이미 소비) 같은 경로로 실패한다 — 메일을 다시 요청해야 한다.
- 이미 로그인한 관리자가 이 경로를 직접 열면 자기 비밀번호를 바꿀 수 있다(세션이 있으므로 통과한다). 별도의 "현재 비밀번호" 확인 단계는 없다.
