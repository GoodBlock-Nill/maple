# <메뉴명> — 화면·기능 설명

> 관리자 콘솔(`admin/`)의 <메뉴명> 메뉴. **화면의 섹션 → 필드/컨트롤 하나하나**가 무엇을 하고, 어떤 검증을 받고, 어떤 서버 액션·DB 변경·클라이언트(사용자 사이트) 변화로 이어지는지를 개발 참고용으로 적는다.
> 작성 규칙: 코드에서 확인한 사실만 쓴다(파일·함수·스키마 이름을 그대로). 파일 경로는 저장소 루트 기준. 워딩은 "카테고리".

## 0. 한눈에
| 항목 | 값 |
|---|---|
| 경로 | `/…` (하위: `/…/[id]`, …) |
| 권한 모듈 | `<module>` — read / write (`admin/lib/auth/permissions.ts`). read 는 무엇을 보고, write 는 어떤 버튼이 더 보이는지 |
| 주요 테이블 | `…`(컬럼 요약) |
| 클라이언트 영향 | 캐시 태그 `…` 재검증 → 사용자 사이트 `/…` 의 어떤 컴포넌트가 바뀌는지 / 없음 |
| 관련 파일 | 페이지 · 컴포넌트 · 액션 · 데이터 · 검증 · 마이그레이션 |

## 1. <화면 이름> (`/경로`)
**목적** 두세 문장. 누가 언제 쓰는 화면인지.

**데이터 출처** 어떤 함수(`admin/lib/data/….ts`)가 어떤 질의로 읽는지, 페이지 크기·정렬 기본값, 조회 실패 시 화면(배너)이 어떻게 되는지.

### 1.1 <섹션 이름> (예: 상태 탭 · 필터 폼 · 표 · 상세 카드 · 답변 폼 · 다이얼로그)
섹션의 역할 한 줄. URL 파라미터를 쓰면 이름과 파싱 규칙(`?status=`, 잘못된 값 → 기본값).

| 필드/컨트롤 | 종류 | 필수·제한(검증) | 기본값·프리필 | 동작 / 상호작용 |
|---|---|---|---|---|
| 제목 | 텍스트 입력 | 1~120자(`newsSchema.title`, DB `posts_title_length`) | 카테고리 템플릿 `title_template` | 저장 시 `posts.title`; 목록·클라이언트 카드 제목 |
| 상단 고정 | 체크박스 | 발행본 기준 최대 3개(`checkPinLimit` + 트리거 `guard_news_pin_limit`) | off | 초과 시 필드 오류 "…(현재 고정: …)"; 클라이언트 카드 핀 아이콘·정렬 |
| 저장 | 버튼 | write 권한 | — | `createNewsAction` → 감사 `news.create/publish` → `news-list` 재검증 → 상세로 이동 |

(표에는 화면에 보이는 **모든** 필드·열·버튼·뱃지를 넣는다. 표의 열이면 "정렬 가능 여부·값의 출처 컬럼·뱃지 색 의미"를, 버튼이면 "확인 다이얼로그 문구·성공/실패 토스트·이동"을, 필터면 "URL 파라미터·유지되는 조건·초기화 동작"을 적는다.)

**상태·뱃지 의미** (있으면) 값 → 라벨 → 색 → 언제 붙는지.

**클라이언트와의 상호작용**
- 이 섹션에서 바꾼 값이 사용자 사이트 어디에(경로·컴포넌트) 어떻게 보이는지, 언제 반영되는지(캐시 태그 / 즉시 / 다음 요청).
- 사용자 사이트에서 들어오는 데이터(접수·신고·등록)가 이 섹션에서 어떻게 보이는지, 사용자가 볼 수 있는 값과 관리자만 보는 값의 차이.

**오류·예외** 실패 문구, 충돌(동시 편집·잠금), 권한 없음, 삭제된 대상 등.
